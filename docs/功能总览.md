## 一、一句话总览

一个**朋友间小规模联机推理游戏**：房主选一道海龟汤（或让 AI 现写），玩家轮流用「是/否」类问题向"汤主"追问，
把汤面背后的真相拼出来；**汤底在结束前对所有人保密**，被猜出时当场对全桌公示。
服务端零常驻进程（无 Durable Objects），状态全在 D1，靠"每请求惰性补算 + 客户端轮询"推进。

## 二、三套前端（同一后端，完全隔离）

| 路径 | 风格 | 会话键 | 定位 |
|---|---|---|---|
| `/` | 深色工装面板（紫青渐变、玻璃卡片） | `ht.token` / `ht.draft` | **主力版**，功能最全（含密钥、参数、AI 创作、复盘） |
| `/deep/` | 深海声呐仪器台（冷色 HUD、声呐环、气瓶倒计时、破水公示） | `ht.deep.*` | 核心玩法版，视觉实验 |

## 三、玩法闭环（用户可见的完整功能）

| 环节 | 玩家做什么 | 服务端行为 |
|---|---|---|
| 建房/加入 | 填名号 +（可选）房号，选火候预设 | `POST /api/rooms`、`POST /api/rooms/:code/join`；发会话令牌；第一个人自动成为房主 |
| 准备 | 非房主点「我已落座/准备好了」 | `ready` 动作；**房主不需要举手**；离线/旁观/房主不计入分母；**断连即撤销准备**；只有 `waiting` 状态接受 |
| 开局 | 房主「就熬这道（选这道）」/「开局（随机）」/「投票选汤」；AI 创作后「就用这道开局」 | `start`（`mode: pick|vote`，可带 `puzzleId`、`force`）；有人在没准备 → 拒绝并**点名**，确认后 `force` 放行；开局清空准备、锁定题目、写入 matches |
| 回合提问 | 轮到自己时输入问题（可预输入草稿） | `submit`；判定引擎给 `是/不是/与此无关/无法回答`；超时进宽限期再跳过；提问一发出即公开、不可撤回 |
| 提示（默认关） | 房主开启后，T1/T2/T3 三档提示 | `hint`；受每人配额、T3 上限、冷却约束；提示来自事实点表原文，不泄汤底 |
| 猜汤底 | 提问框旁「揭开汤底 / 破水」，**随时可猜**；全桌共用一个冷却（房主可设 0–1800 秒）；每人上限默认不限 | `guess`；判定看关键要素是否齐 + 有无因果链；命中 → 本局 `solved`；接近（≥60%）只回数量不回明细；**任何一次猜（对错都算）都会重置共用冷却** |
| 汤底公示 | 被猜出的那一刻，**所有人**同时看到汤底（弹窗 + 页面卡片） | 房间投影里出现 `truth`/`truthNote`；这是"汤底永不下发"的唯一例外 |
| 复盘（仅房主） | 「查看复盘」：汤底 + 全部提问与判定 + 成员数据 | `GET /api/recap`；仅房主、仅 `settled`、中止局不揭晓 |
| 结束/下一局 | 房主「收锅（结束）」或猜出后「开下一锅」 | `end_match`（aborted，**不公示汤底**）；`next_round` 把房间放回 `waiting`：清题目/结果/冷却/回合，可再选下一道 |
| 离席/踢人 | 任意玩家「离席」；房主把某人「移出」 | `leave`（**最后一人离开会立刻物理清理房间**）；`kick`（吊销其全部会话） |
| 房主失联 | 断连触发移交；原房主回来可归还 | 移交时原房主 Key 挂起、额度切平台；`resume_transfer`/`return_host`/`decline_return` |
| AI 中断 | 模型鉴权失败/限流时对局暂停 | `room.ai.state=BLOCKED` → 房主「更新 Key 并继续」或「撤销改用平台额度」；也可发起投票临时启用平台额度 |
| 全员讨论（新增） | 任何成员（含旁观者、待入席）在侧栏「讨论」里自由发言，商量下一步问什么 | `chat` 动作 → 独立表 `room_chat`、独立游标 `chatSeq`；限长 500 字、清控制字符（**不做 NFKC**，中文全角标点原样保留）、独立限流 10 秒 5 条 / 60 秒 30 条；`clientMessageId` 幂等（**按发送者**去重，重试不产生重复消息）。**不参与判定**：不进模型、不占回合、不进缓存、不加线索、不触发猜底；房间被清理时随房间一起删除 |

讨论区的前端行为（设计稿 §12.3/§12.4/§12.7）：

- 桌面端是侧栏常驻卡片；**窄屏收成一个「讨论」入口按钮（带未读角标）**，点开是近全屏面板（`100dvh`、顶部「← 返回」、输入框贴底、打开时锁住页面滚动）。
- 点「发送」**乐观显示**：自己那条立刻上屏（实测 10–15 ms），不等服务端往返；真值回来按 `clientMessageId` 原地替换，不重复、不跳动；失败则撤回本地那条并把草稿退回输入框。
- 未读只算别人发的；**看得见且停在底部**才算已读。往上翻旧消息时新消息不强行拉到底，改为右上角「有 N 条新消息 ↓」入口，点了才跳。
- 讨论草稿只在内存，与正式提问草稿（`localStorage.ht.draft`）互不覆盖；Enter 发送 / Shift+Enter 换行，输入法组字期间不误发。
- 用户把光标留在输入框里时整页重渲染会被推迟（保护输入法组字），此时讨论区走**局部补渲染**，消息照常出现。
- **跨局分隔线**（§12.8）：每条消息记下"发它时的局号"，局号变化处插一条「第 N 局开始」，旧消息仍可回看但一眼看得出分界；
  局号跟着"开局"递增（回到选题不清零，`roundNo` 清它不清）。

## 四、判定引擎（判定的"权威"不是模型）

1. **事实点表**是判决依据：每题 3–10 条原子事实（`isTrue` 真/假、`tier` 1–3、`required` 必需、`keys` 关键词）。
2. 模型只做**映射**：把玩家的问题映射到事实点，答案（是/否/无关/无法回答）由事实表裁决。
3. **判定缓存**：按 `题目 + 问题哈希 + prompt 版本 + 事实点版本` 命中，省调用；带 `scale-v1` 尺度版本，便于事后归因。
4. **揭秘判定**（纯规则）：必需事实全中 + 表达因果链 = 命中；≥60% = 接近；有矛盾事实则降级。
5. **坏题检测**（`checkAndNormalizePuzzle`）：结构、长度、层级完整性（必须同时有 tier1 与 tier2 的成立事实）、
   汤面不得泄露关键事实原文、违禁内容分组（超自然/性暴力/猎奇血腥/科幻灾难/繁体变体）——不通过则整题作废。

## 五、凭据与额度（钱归谁出，写得明明白白）

优先级：**① 房主自备 Key → ② 平台额度（`AI_KEY`，受 `SITE_MONTHLY_CALL_CAP` 约束）→ ③ 内置模拟主持人**（离线可玩，纯关键词匹配）。

- 自备 Key 存进**密钥保险箱**（AES-GCM 主密钥加密），任何角色都取不回明文，只能看到掩码；所有权不可转移。
- **调用失败不自动降级**（避免静默烧平台的钱）：失败即暂停，等房主处理；临时启用平台额度要**全员投票**。
- 每次模型调用记 `usage_counters`（site/host 分开），关键动作落 `audit_events`。

## 六、保密红线（代码里是硬约束，不是口号）

- 汤底原文、事实点原文、密钥明文**永不下发**；题目投影走白名单（`toPublicPuzzle`），房间投影走 `assertNoLeak` 运行时兜底断言。
- 唯一的例外是**被猜出后的汤底公示**，且必须显式声明 `allowTruth: true` —— 忘了声明会直接抛错（有测试钉住）。
- 中止（aborted）与没猜出来的局一律 `truth = null`（防"开局→立刻结束→读汤底"）。
- 复盘的汤底只由服务端在门禁通过后注入；`/api/recap` 仅房主。

## 七、技术架构（方案 A：D1 + 轮询，无 Durable Objects）

- **每请求三步**：① D1 载入快照 → ② 复用纯函数运行时（`RoomRuntime`/`HostService`，与 Node 参考服务器同一份代码）→
  ③ 单事务写回（房间 `state_version` CAS + 带守卫的派生写入），冲突最多重放 3 次，仍冲突返回 409。
- **惰性补算**：每个请求先跑 tick（超时跳过/挂机/移交/投票截止），等价于"每秒 tick"，因此不需要常驻定时器。
- **事件流**：动作响应里直接带回最新视图 + 本次事件（自己操作零额外往返）；广播帧落 `room_events` 供增量拉取。
- **回收**：最后一人离开即物理清理（含密钥密文）；Cron `17 * * * *` 扫描过期房间。
- **表**：`rooms` `members` `sessions` `questions` `verdict_cache` `matches` `credentials` `credit_grants` `usage_counters` `audit_events` `room_events`
  （迁移 `0001`–`0005`，线上已应用）。
- **安全**：CSP 等安全响应头、昵称清洗、令牌只存 sha256、Base URL 走 SSRF 校验（仅 https、禁内网/回环/query）、限流、401/404/409 语义分明。
