## 一、一句话总览

一个**朋友间小规模联机推理游戏**：房主选一道海龟汤（或让 AI 现写），玩家轮流用「是/否」类问题向"汤主"追问，
把汤面背后的真相拼出来；**汤底在结束前对所有人保密**，被猜出时当场对全桌公示。
服务端零常驻进程（无 Durable Objects），状态全在 D1，靠"每请求惰性补算 + 客户端轮询"推进。

## 三、玩法闭环（用户可见的完整功能）

| 环节 | 玩家做什么 | 服务端行为 |
|---|---|---|
| 建房/加入 | 填名号 +（可选）房号，选火候预设 | `POST /api/rooms`、`POST /api/rooms/:code/join`；发会话令牌；第一个人自动成为房主 |
| 准备 | 非房主点「我已落座/准备好了」 | `ready` 动作；**房主不需要举手**；离线/旁观/房主不计入分母；**断连即撤销准备**；只有 `waiting` 状态接受 |
| 开局 | 房主「就熬这道（选这道）」/「开局（随机）」/「投票选汤」；AI 创作后「就用这道开局」 | `start`（`mode: pick|vote`，可带 `puzzleId`、`force`）；有人在没准备 → 拒绝并**点名**，确认后 `force` 放行；开局清空准备、锁定题目、写入 matches |
| 回合提问 | 轮到自己时输入问题（可预输入草稿）；**回车发送**、Shift+回车换行（输入法组字期间的回车不会误发） | `submit`；判定引擎给 `是 / 不是 / 部分接近 / 与此无关 / 无法回答`，并**每次都附一句结合提问语境的说明**（如「否——你问的『门锁着』在本局设定里不成立」）；**一句话里问了两件事、只说对一半时回「部分接近」**；说明由模型给出、服务端做泄露与引导式措辞清洗，模型没给就用玩家自己的问法兜一句；超时进宽限期再跳过；提问一发出即公开、不可撤回 |
| 提示（默认关） | 房主开启后，T1/T2/T3 三档提示 | `hint`；受每人配额、T3 上限、冷却约束；提示来自事实点表原文，不泄汤底 |
| 猜汤底 | 提问框旁「揭开汤底 / 破水」，**随时可猜**；全桌共用一个冷却（房主可设 0–1800 秒）；每人上限默认不限 | `guess`；判定看关键要素是否齐 + 有无因果链；命中 → 本局 `solved`；接近（≥60%）只回数量不回明细；**任何一次猜（对错都算）都会重置共用冷却** |
| 汤底公示 | 被猜出的那一刻，**所有人**同时看到汤底（弹窗 + 页面卡片） | 房间投影里出现 `truth`/`truthNote`；这是"汤底永不下发"的唯一例外 |
| 复盘（仅房主） | 「查看复盘」：汤底 + 全部提问与判定 + 成员数据 | `GET /api/recap`；仅房主、仅 `settled`、中止局不揭晓 |
| 结束/下一局 | 房主「收锅（结束）」或猜出后「开下一锅」 | `end_match`（aborted，**不公示汤底**）；`next_round` 把房间放回 `waiting`：清题目/结果/冷却/回合，可再选下一道 |
| 离席/踢人 | 任意玩家「离席」；房主把某人「移出」 | `leave`（**最后一人离开会立刻物理清理房间**）；`kick`（吊销其全部会话） |
| 房间自动回收 | 玩到一半直接关掉网页（没点「离席」）也不会留下僵尸房间 | 见下方「房间生命周期」：**没状态变化、也没人心跳**超过 6 小时 → 销毁（Cloudflare Cron 每小时 :17 扫一次 + 每分钟的 Node 参考实现；每次销毁都写 `room_destroyed` 审计） |
| 房主失联 | 断连触发移交；原房主回来可归还 | 移交时原房主 Key 挂起、额度切平台；`resume_transfer`/`return_host`/`decline_return` |
| AI 中断 | 模型鉴权失败/限流时对局暂停 | `room.ai.state=BLOCKED` → 房主「更新 Key 并继续」或「撤销改用平台额度」；也可发起投票临时启用平台额度 |
| 全员讨论（新增） | 任何成员（含旁观者、待入席）在侧栏「讨论」里自由发言，商量下一步问什么 | `chat` 动作 → 独立表 `room_chat`、独立游标 `chatSeq`；限长 500 字、清控制字符（**不做 NFKC**，中文全角标点原样保留）、独立限流 10 秒 5 条 / 60 秒 30 条；`clientMessageId` 幂等（**按发送者**去重，重试不产生重复消息）。**不参与判定**：不进模型、不占回合、不进缓存、不加线索、不触发猜底；房间被清理时随房间一起删除 |
| 候选题（等待阶段） | 房主看 2 道候选，可「换一批」 | 默认按房间号做种子从题库取 2 道（同房间稳定）；`reroll_candidates` 只读动作从题库真随机另抽 2 道（避开当前这批）。换出来的那一批活在当前等待阶段的前端内存里，刷新页面会回到默认那批 |

讨论区的前端行为（设计稿 §12.3/§12.4/§12.7）：

- 桌面端是侧栏常驻卡片；**窄屏收成一个「讨论」入口按钮（带未读角标）**，点开是近全屏面板（`100dvh`、顶部「← 返回」、输入框贴底、打开时锁住页面滚动）。
- 点「发送」**乐观显示**：自己那条立刻上屏（实测 10–15 ms），不等服务端往返；真值回来按 `clientMessageId` 原地替换，不重复、不跳动；失败则撤回本地那条并把草稿退回输入框。
- 未读只算别人发的；**看得见且停在底部**才算已读。往上翻旧消息时新消息不强行拉到底，改为右上角「有 N 条新消息 ↓」入口，点了才跳。
- 讨论草稿只在内存，与正式提问草稿（`localStorage.ht.draft`）互不覆盖；Enter 发送 / Shift+Enter 换行，输入法组字期间不误发。
- 用户把光标留在输入框里时整页重渲染会被推迟（保护输入法组字），此时讨论区走**局部补渲染**，消息照常出现。
- **自己的便笺不做入场动画**（只有别人发的便笺才"贴进来"一次）：自己那条会在同一个 tick 里被渲染两次
  （本地乐观条目 + 服务端响应触发的整页渲染），只要它带动画就会重建节点、重播动画，看起来就是"自己发的字在闪"。
  从规则上不给自己的便笺加动画，这一类闪烁就不存在了。
- **跨局分隔线**（§12.8）：每条消息记下"发它时的局号"，局号变化处插一条「第 N 局开始」，旧消息仍可回看但一眼看得出分界；
  局号跟着"开局"递增（回到选题不清零，`roundNo` 清它不清）。

### 3.3 微动效（小转场）

目标是"不那么生硬"，全部只用 `opacity` / `transform`（不改布局、不加渐变与阴影），
并且**同一条纪律**：动画**绝不挂在常驻节点上** —— 整页是 `innerHTML` 全量重渲染，
常驻动画每次重渲染都会重播（这正是之前"自己发的字在闪"的根因）。

| 场景 | 效果 |
|---|---|
| 换屏（入口 ⇄ 房间） | 整屏 200ms 上浮淡入（`screen-in`） |
| 右栏切页签 | 面板 160ms 上浮淡入（`panel-in`） |
| 汤面出现、轮到你的提示、公告条 | 180ms 淡入上浮；"轮到你"从左侧滑入（`card-in`） |
| 弹窗打开 | 遮罩 120ms 淡入 + 卡片 180ms 上浮（`curtain-in`） |
| 弹窗关闭 | **先播 130ms 淡出再真正移除**（`closeWithFx`）——否则是"啪"地消失 |
| 短提示（窄收据） | 从右侧滑入；到期前 200ms 先淡出再移除 |
| 倒计时进度条 / 机械刻度 | 宽度 250ms 线性过渡、刻度亮灭 180ms 渐变（不再一格一格跳） |
| 按钮 / 候选卡 / 页签 | hover 底色过渡、按下 1px 回弹、候选卡 hover 边框抬亮 |

实现要点（`fxEnter()`）：入场动画只在该元素"**刚出现/刚变化**后的 260ms 窗口内"补类。
不用"值变了才播一次"的简单写法，是因为入场后往往紧跟一次渲染（建房/开局的响应 + 紧接着的轮询），
那次渲染会把刚加的类连同节点一起换掉，动画还没开始就没了 —— 表现就是"根本没有转场"。
窗口内同值再渲染允许重新起播（肉眼看不出来），窗口过了就再也不补，避免重播。
`prefers-reduced-motion: reduce` 下所有动画与过渡全部关闭（既有规则，新加的一并生效）。

### 3.2 单人模式（自己推一道题）

入口页第三个按钮「**单人模式**」：进的是**同一套房间与同一套判定代码**，只是建房时带 `solo: true`。

| 单人模式**没有**什么（服务端直接拒绝，不只是界面不显示） | 单人模式**一样有**什么 |
|---|---|
| 全员讨论区（`chat`） | 提问判定 + 那句结合语境的说明（含「部分接近」） |
| 准备举手（`ready`）、等房主开局 | 提示 T1/T2/T3、猜汤底（含冷确与"接近"反馈） |
| 投票选汤 / 投票启用平台额度（`vote`） | 汤底公示、复盘、AI 创作题目、换一批候选题 |
| 踢人（`kick`）、房主移交三件套 | 对局参数（多人专属项自动隐藏）、记录、连接状态 |
| **回合倒计时与超时跳过** | 额度来源与自备 Key 管理（AI 异常可恢复） |

- **不计时**：`deadlineAt / graceDeadlineAt = 0` 表示不限时（`canSubmit` 不判过期、`tickTurn` 不推进阶段）。
  多人里的倒计时是为了公平轮换，一个人时只会平白制造"超时跳过"的噪音，还会把回合数一路烧到上限。
- **挂机不跳过、也不暂停**：一个人"挂机"只是在想题。多人房那条「全员挂机 → 暂停对局」的规则对单人房不适用
  （否则回来会看到"已暂停 · 全员挂机"，而单人房又没有房主移交那套恢复动作）。
- **别人进不来**：`POST /api/rooms/:code/join` 对单人房返回 403 `SOLO_NO_JOIN`。
- 多出来的 `maxRounds` 语义：单人里"一轮"就是"一问"，所以它变成**本局提问次数上限**（改文案不改规则）。
- 生命周期与多人一致：最后一人离开即物理清理；关掉网页 6 小时由 Cron 回收（§3.1）。
- 多人专属动作的名单只有一份（`core/constants.ts` 的 `SOLO_BLOCKED_ACTIONS`），
  Node 参考实现与 Worker 都读它 —— 不会出现"界面藏了、接口还放行"的缝隙。

### 3.1 房间生命周期（什么时候会被收掉）

房间**不是**长期存档：所有关联数据（提问记录、讨论、密钥密文、回合事件）都随房间一起删除。
四条规则，按优先级：

| 触发 | 行为 |
|---|---|
| 最后一名成员点「离席」 | **立刻**物理清理（`purgeRoom`：房间 + 成员 + 会话 + 提问 + 讨论 + 事件 + 密钥密文） |
| 成员表为空（异常残留） | Cron 下一轮清掉 |
| 未开局（`waiting`）超过 `PLATFORM.roomWaitExpireSec`（6 小时） | 销毁：光挂着不开局的房间不留 |
| **没人了**：既没有状态变化、也没有任何成员心跳，都超过 `PLATFORM.roomDestroySec`（**6 小时**） | 销毁。这是"晚上玩完直接关网页、第二天早上打开不该还被拉回那个房间"的那条规则 |

**为什么心跳要算进来**（`core/room.ts` 的 `isRoomAbandoned()`）：`updatedAt` 只在**状态变化**时刷新
（提问、回合推进、投票…），心跳不改房间状态 —— 只看 `updatedAt` 的话，
"页面开着但大家都没操作"和"浏览器已经关了"两种房间长得一模一样，会把前者一起收走。
心跳（20 秒一次）是"这一端还开着页面"的唯一可靠信号：
**只要还有任何一个页面开着，房间就不会被回收**（挂机由回合超时/跳过各自处理，不影响房间存活）；
网页关了 → 心跳停止 → 到点收走。

实现：Cloudflare 侧是 Cron `17 * * * *`（`wrangler.toml` 的 `[triggers]`，免费计划可用）
扫 `listPurgeableRooms()` 并 `purgeRoom()`；Node 参考实现是 `RoomRegistry.sweepLifecycle()`（每分钟）。
两边读同一个常量，判据一致。每次销毁都写一条 `room_destroyed` 审计
（`subject` = 原因、`result` = `cron`），所以"房间什么时候没的、为什么没的"事后查得到。
客户端在「回到我的房间」失败时（房间已被回收）会清掉旧令牌并给一句中文说明，不会甩错误码。

## 四、判定引擎（判定的"权威"不是模型）
1. **事实点表**是判决依据：每题 3–10 条原子事实（`isTrue` 真/假、`tier` 1–3、`required` 必需、`keys` 关键词）。
2. 模型只做**映射**：把玩家的问题映射到事实点，答案由事实表裁决。**五类结论**：
   | 结论 | 玩家看到 | 触发条件（全部可机判） |
   |---|---|---|
   | `yes` | 是 | 命中的事实点**全部成立** |
   | `no` | 否 | 命中的事实点**全部不成立** |
   | **`partial`** | **部分接近** | 命中的事实点**真假混杂** —— 玩家一句话里问了两件事，只说对了一部分 |
   | `irrelevant` | 无关 | 一条都没命中（封闭世界假设：问的要素本题没出现，**不是"否"**） |
   | `unanswerable` | 无法回答 | 元提问 / 批量列举 / 开放提问 / 世界外 / 越狱 / 索取汤底，必须带 `reasonCode` |

   `partial` 是**为玩家真实问法加的**：玩家不会一条一条问，他会说「他是不是因为内疚才下毒的？」
   ——「内疚」成立、「下毒」不成立。以前只会命中成立的那条、答「是」，等于默认了不成立的那半句；
   现在如实回「部分接近」，而且**绝不指出哪一半对**（那就是免费提示）。
   模型侧的要求是"把问到的事实点都填进 `matched_fact_ids`"（≤3 条），最终由 `decideFromFacts()` 裁决。
   注意区分：用**逗号**把两件事分开问（「…，还是…？」）走的仍是既有的
   「一次只问一件事，请拆开再问」（`COMPOUND_SPLIT_REQUIRED`）——那是"自己知道是两件事"的写法。
3. **判定缓存**：按 `题目 + 问题哈希 + prompt 版本 + 事实点版本` 命中，省调用；带 `scale-v1` 尺度版本，便于事后归因。
4. **揭秘判定**（纯规则）：必需事实全中 + 表达因果链 = 命中；≥60% = 接近；有矛盾事实则降级。
5. **坏题检测**（`checkAndNormalizePuzzle`）：结构、长度、层级完整性（必须同时有 tier1 与 tier2 的成立事实）、
   汤面不得泄露关键事实原文、违禁内容分组（超自然/性暴力/猎奇血腥/科幻灾难/繁体变体）——不通过则整题作废。

### 4.1 模型异常与格式错误的兜底（逐层）

模型的输出永远不可信，所以每一层都有自己的兜底，且**任何一层失败都不会把原始输出展示给玩家**：

| 层 | 兜的是什么 | 具体做法 |
|---|---|---|
| ① 输入预检 L0 | 提示注入 / 元问题 / 批量列举 / 开放式提问 | `preflight()` 命中就直接给结论（`unanswerable` + 原因码），**不调用模型**（不花钱、不受模型状态影响） |
| ② 请求参数 | **思考模式把输出预算吃光**（爆思维链的根因） | DeepSeek 端点显式 `thinking:{type:'disabled'}` + `reasoning_effort:'low'`；`response_format=json_object`；判定 `max_tokens` 起步 400（出题 1800） |
| ③ 传输 | 超时 / 连接重置 / 401·402·403·404·408·425·429·5xx / 上游拒答 | AbortController 超时、逐状态码分类、`message.refusal` → `PROVIDER_REFUSAL` |
| ④ 解析 | 围栏 ```` ```json ````、前后散文、**正文里混着示例 JSON**、结尾被截断 | `extractJsonObject()`：整体 → 去围栏 → 扫**所有**平衡的 `{...}` 取"字段最多/最靠后"的那个 → 补引号补括号；判定路径先用"不做补救"的严格模式，只有非截断时才接受补救结果 |
| ⑤ 语义校验 L3 | 枚举越界、多余字段、未知事实点、yes/no/**partial** 与事实点不自洽、unanswerable 滥用、**复述汤底** | `validateJudgeOutput()` 白名单 + 自洽性 + 8-gram 泄露检查（`explanation`/`reasoning`/`thought` 这类越界字段一律整条拒绝，防止夹带）；`partial` 还要求至少命中两条（只命中一条那是"一件事"，谈不上部分） |
| ⑥ 重试与降级 | 一次性故障 | 可重试类（超时/连接/限流/5xx/格式错/**截断**/**只回思考**）退避重试，**且重试时把 `max_tokens` 翻倍**（400→800→1600）；L3 语义错误不重试（同一提示词重试大概率再犯） |
| ⑦ 失败后的对局处理 | 模型彻底不可用 | 暂停对局（`ai_blocked`）并写明原因码 → 房主换 Key/换模型，或全员投票临时启用平台额度；**绝不自动降级烧平台的钱**；完全没有凭据时用内置模拟主持人（离线可玩） |
| ⑧ 诊断安全 | 排错时把汤底写进日志 | 日志预览走 `leakSafePreview()`，与汤底重合的片段整体打码 |
| ⑨ 结论复核后的说明自洽 | 模型"命中成立的事实点却说否"，事实表改判后留下自相矛盾的说明 | `decideFromFacts()` 复核结论（模型只做映射）；被改写时 `coherentExplain()` 丢掉说反的那句说明、由 `contextExplain()` 用玩家自己的问法兜一句，并把**模型原本的答案**记进 `questions.answer_model` 留痕 |
| ⑩ 说明句的取舍 | 模型爱写「你问的『X』在本题设定里没有提到」这类**样板说明**：只是把结论重说一遍，连着几行都是它反而淹掉有信息的说明 | `finalExplain()` 是唯一出口：样板句丢掉；`irrelevant` 干脆不带说明（与「无关」完全重复），是/否/部分接近/无法回答换成点明"结论管的是问题里哪一部分"的兜底句；真正有内容的说明照常保留 |
| ⑪ 部分接近不许说破 | 模型"好心"告诉玩家哪半句对了 | `partial` 的说明只允许说"一部分"，**不得指出哪部分成立**（那是免费提示）；提示词里明令禁止，清洗层再兜一道（引导式措辞一律丢弃） |

单独的失败类型（都能在界面上一眼看懂该做什么）：`OUTPUT_TRUNCATED`（被 max_tokens 截断）、
`THINKING_ONLY`（只回思考过程、正文为空）、`SCHEMA_INVALID`（不按格式说）、`LEAK_DETECTED`（输出含汤底片段，已拦）。

**判定体检（"这条记录是模型判错还是系统判错"）**：`pnpm audit` 现在多打两张表 ——

- `③a` 列出**结论被事实表改写过的**记录：`answer_model`（模型原本说 what）对比 `answer`（最终结论）
  + 命中的事实点 + 那句说明。正常情况这张表为空；一旦有行，就能立刻看出是模型映射错了还是题目事实点写得有问题。
- `③b` 列出**说明句与结论自相矛盾**的记录（例如 `answer=yes` 却写了「否——…」）。这条查询**正常情况下恒为 0 行**，
  是上面第 ⑨ 层兜底的回归指标。

## 五、凭据与额度（钱归谁出，写得明明白白）

优先级：**① 房主自备 Key → ② 平台额度（`AI_KEY`，受 `SITE_MONTHLY_CALL_CAP` 约束）→ ③ 内置模拟主持人**（离线可玩，纯关键词匹配）。

- 自备 Key 存进**密钥保险箱**（AES-GCM 主密钥加密），任何角色都取不回明文，只能看到掩码；所有权不可转移。
- **调用失败不自动降级**（避免静默烧平台的钱）：失败即暂停，等房主处理；临时启用平台额度要**全员投票**。
- 每次模型调用记 `usage_counters`（site/host 分开），关键动作落 `audit_events`。

### 5.1 审计里记什么（含客户端 IP 的处理）

`audit_events` 一行 = 一次可追责的动作：`action`（`member_joined`/`member_left`/`member_kicked`/`room_created`/
`room_destroyed`/`chat_posted`/`guess_submitted`/`host_skip_turn`/`host_transferred`/`config_updated`/`credential_submitted`/
`ai_blocked`/`ai_puzzle_created`/`ai_puzzle_rejected` …）、`room_id`、`actor`、`subject`、`result`、`ts`、`meta_json`。

**客户端 IP 只以加盐哈希形式记录**（`ip_hash`）：

- 算法是 **HMAC-SHA256**（域分隔前缀 `ht-ip-v1:`，取前 16 位十六进制）。**刻意不用** `sha256(盐 + IP)`：
  IPv4 只有 2³² 个取值，拿到哈希 + 公开盐几秒就能反查全表 —— 那等于存了明文 IP。
- 密钥来源：Worker 用部署密钥 `MASTER_KEY`（可用 `IP_HASH_SALT` 覆盖）；Node 参考服务器同样优先 `MASTER_KEY`，
  其次 `IP_HASH_SALT`，都没有则用"仅限本地开发"的固定值。**没有密钥时干脆不记**（不写弱哈希、不写假的 "unknown" 桶）。
- **原始 IP 绝不落库、绝不进日志、绝不下发**：日志策略里明确写着"绝不记录完整 IP（只留 ip_hash）"。
  有测试会把整张库导出来断言里面找不到 `127.0.0.1` / `::ffff:127.0.0.1`。
- IP 来源只认 Cloudflare 注入的 `CF-Connecting-IP`（边缘会覆盖客户端伪造的同名头），不读可伪造的 `X-Forwarded-For`。
- 用途仅限反滥用（例如同一个来源疯狂建房/刷消息）；同 IP 同密钥的哈希稳定，因此**可以按来源聚合，但推不出是谁**。
- 注意：审计行**不会**随房间清理而删除，也不做自动过期（TTL）。要按天/周清理需要额外加一个清理任务（目前没做）。

## 六、保密红线（代码里是硬约束，不是口号）

- 汤底原文、事实点原文、密钥明文**永不下发**；题目投影走白名单（`toPublicPuzzle`），房间投影走 `assertNoLeak` 运行时兜底断言。
- 唯一的例外是**被猜出后的汤底公示**，且必须显式声明 `allowTruth: true` —— 忘了声明会直接抛错（有测试钉住）。
- 中止（aborted）与没猜出来的局一律 `truth = null`（防"开局→立刻结束→读汤底"）。
- 复盘的汤底只由服务端在门禁通过后注入；`/api/recap` 仅房主。

## 七、技术架构（方案 A：D1 + 轮询，无 Durable Objects）

- **每请求三步**：① D1 载入快照 → ② 复用纯函数运行时（`RoomRuntime`/`HostService`，与 Node 参考服务器同一份代码）→
  ③ 单事务写回（房间 `state_version` CAS + 带守卫的派生写入），冲突最多重放 3 次，仍冲突返回 409。
- **惰性补算**：每个请求先跑 tick（超时跳过/挂机/移交/投票截止），等价于"每秒 tick"，因此不需要常驻定时器。
- **事件流**：动作响应里直接带回最新视图 + 本次事件（自己操作零额外往返）；广播帧落 `room_events` 供增量拉取。
- **回收**：最后一人离开即物理清理（含密钥密文）；Cron `17 * * * *` 扫描"没人了"的房间
  （无状态变化 **且** 无心跳超过 6 小时 → 销毁，并写一条 `room_destroyed` 审计）。
- **表**：`rooms` `members` `sessions` `questions` `verdict_cache` `matches` `credentials` `credit_grants` `usage_counters` `audit_events` `room_events`
  （迁移 `0001`–`0005`，线上已应用）。
- **安全**：CSP 等安全响应头、昵称清洗、令牌只存 sha256、Base URL 走 SSRF 校验（仅 https、禁内网/回环/query）、限流、401/404/409 语义分明。

- **页面**：`/`（深夜档案桌，主力版）· `/classic/`（旧版深色工装，回滚用）· `/desk/`（跳转页）· `/deep/`（深海）· `/lodge/`（汤屋）
- **HTTP**：`GET /api/config` · `GET /api/health` · `GET /api/session` · `POST /api/rooms`（`{ nickname, preset, config?, solo?: true }`）· `POST /api/rooms/:code/join` ·
  `GET /api/rooms/state?since=` · `POST /api/rooms/actions` · `POST|DELETE /api/credentials` · `POST /api/credentials/test` · `GET /api/recap`（仅房主）· `/ws` → 410（已改轮询）
- **动作**：`heartbeat` `activity` `submit` `hint` `guess` `vote` `config` `start` `ready` `kick` `create_ai_puzzle`
  `next_round` `skip_turn` `end_match` `resume_transfer` `return_host` `decline_return` `reenable_key` `revoke_key` `leave` `chat`
  `reroll_candidates`（房主换一批候选题；只读动作，不改房间状态）
- **单人房额外拒绝**（`SOLO_NO_MULTIPLAYER`，加入则是 `SOLO_NO_JOIN`）：`chat` `vote` `ready` `kick` `skip_turn`
  `resume_transfer` `return_host` `decline_return`
- **存在性阈值**（客户端只能上报原始信号，状态由服务端按时间推导）：心跳 20 秒一次；
  挂机＝前台 10 分钟无操作 / 后台标签页 30 分钟；断连＝3 分钟没有心跳；
  房主断连移交宽限 30 秒、移交冷却 5 分钟、每局最多 3 次。
