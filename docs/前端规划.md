# 前端重构规划（依据 `docs/前端设计方案.md`）

> 设计依据：`docs/前端设计方案.md`（我方方案，26 节，对象＝主力前端 `/`）
> 现状依据：`docs/功能总览.md` · 三套前端 `/`（深色工装）· `/deep/` · `/lodge/`
> 本规划只把那份方案**排成可执行的阶段**，不新增方案之外的玩法。

---

## 一、范围与不变项（先划死）

**要做**
1. 按「深夜档案桌」美术概念**重写主力前端 `/`** 的界面与交互呈现（配色/字体/形状/各区格式/信息架构/响应式/可访问性）。
2. 唯一新增功能：**全员讨论区**（§12）——含它需要的最小后端与数据（§12.9）。
3. 把英文内部状态统一换成中文界面文案（§24）。

**不做**（方案已写明）
- 不新增其它玩法、接口、角色、自动流程（**不**做"自动下一局"）。
- `/deep/`（深海声呐）与 `/lodge/`（深海汤屋）保持为隔离的视觉实验版，本次不动。
- 风格禁区：AI 味蓝紫渐变、玻璃拟态、霓虹光晕、悬浮胶囊、emoji 拼装界面（图标改**单色线性 SVG**）。

## 二、交付策略：先影子、后切换

主力 `/` 是正在使用的版本，直接原地重写风险高。因此：

1. 先把新界面做在 **`/desk/`**（第四套，同样隔离：独立 localStorage 键 `ht.desk.*`），可与现有 `/` **并排对比**；
2. §25 验收清单全绿 + 你确认后，一次提交把 `/desk/` 提升为 `/`（旧文件保留为 `/classic/` 便于回滚）。

### M3 · 全员讨论区（唯一新增功能，1.25 天）
**前端**：§12.3/12.4 桌面与移动布局、§12.5 消息样式、§12.6 输入与发送状态、§12.7 未读与滚动。
**后端（本次唯一要动的服务端）**：
| # | 项 | 设计 |
|---|---|---|
| 3.1 | 表 | D1 迁移 `0006_room_messages.sql`：`room_messages(id, room_id, match_id, member_id, text, created_at)` + `(room_id, created_at)` 索引；Node store 同步迁移 |

### M5 · 移动端、反馈与可访问性（0.75 天）
§6 移动端（单列顺序：状态 → 汤面 → 输入(吸附) → 记录 → 讨论 → 名册）、§21 三类反馈（短提示/持续/错误）、§22 响应式、§23 可访问性（焦点可见、44×44 触摸目标、Tab 顺序、`prefers-reduced-motion` 全关动效）。验收：移动端与稳定性 5 项。

### M6 · 验收与切换（0.5 天）
1. 按 §25 逐条打勾（8 组、约 40 项），我把可自动化的一律脚本化：
   - **视觉**：`grep` 断言无 `backdrop-filter`／无 emoji 图标／无蓝紫渐变；
   - **对比度**：脚本计算所有前景/背景组合 ≥ 4.5:1（正文）；
   - **触摸与键盘**：CDP 遍历可交互元素，断言尺寸 ≥44×44、Tab 可达、`Esc` 关弹窗；
   - **三态一致**：`/desk/` 与 `/` 同时开两个房间，对比状态文案一致；
2. CDP 实跑完整多人对局（复用现有 `ht-play` 脚本）+ 截图存档到 `data/前端验收/`；
3. 切换：`/` → 新界面，旧版移到 `/classic/`；更新 `docs/功能总览.md` 的前端表；
4. `pnpm test`、`tsc`、`selfcheck` 全绿后提交推送（CI/CD 自动部署）。

## 四、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 原地重写主力版出错，影响正在用的人 | 高 | 影子路径 `/desk/` 先做，验收后再切换；旧版留 `/classic/` 可一键回滚 |
| 「不用 emoji、图标全自绘」工作量被低估 | 中 | M0 先做 12 个线性图标的 sprite，后续只增量补 |
| 讨论区引入后端面（表/接口/限频/清理） | 中 | 严格按 §12.9 最小范围；纳入既有轮询与 purge 流程，不加新机制 |
| 平面+描边风格层级不足，信息反而更难扫 | 中 | 用"三种纸 + 三种标签（纸签/印章/短横线）"建立层级差；M2 后用截图做真实对照 |
| 方案里"降低房主功能视觉优先级"导致找不到入口 | 低 | 房主功能收进顶栏右侧两个入口（额度/参数），保留常驻但低权重 |

## 五、估时与最小可交付

- 全量：约 **6 人日**（M0–M6）。
- **最小可交付（建议先做）**：M0 + M1 + M2 + M5 的移动端部分 ≈ 3 人日，就能得到一个"深夜档案桌"风格的完整对局界面（讨论区与房主弹窗暂沿用旧版交互）。
- 讨论区（M3）单独可切：不做也不影响其余部分上线。
